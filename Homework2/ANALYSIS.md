## Висновки

### 1. Коли використовувати Ollama (self-hosted)?

**Використовуй Ollama якщо:**
- **Приватність даних критична** — медичні, банківські, юридичні документи, які не можна відправляти в хмару
- **Офлайн-середовище** — production на ізольованих серверах (defense, banking), без доступу до інтернету
- **Бюджет нульовий після покупки GPU** — після одноразової інвестиції в GPU вартість inference = $0
- **Прості або короткі запити англійською** — для української мови якість 7B моделі суттєво гірша
- **Великий обсяг запитів** — при 10M+ запитів/місяць OpenAI дорожче, self-hosted окупається

**Мінімальні критерії якості для вибору self-hosted:**
- Для structured output (JSON) на українській потрібна модель ≥ 13B параметрів, краще 70B
- З GPU час відповіді: 5–30 секунд замість 4–6 хвилин на CPU
- Якщо точність задачі < 80% прийнятна → можна використовувати 7B

**Що показав експеримент:**
- Llama2 7B на CPU дав 100% JSON-валідність, але з помилками у даних (owner swap, мовні провали, пропущені задачі)
- Recall падає з 100% (simple) до 67% (technical) при збільшенні складності тексту
- Модель ігнорує інструкцію щодо мови — переходить на англійську

### 2. Коли використовувати OpenAI API (cloud)?

**Використовуй OpenAI якщо:**
- **Якість критична** — 100% точність екстракції, правильна схема JSON, нульові галюцинації
- **Швидкість важлива на слабкому залізі** — 3–5 секунд cloud API проти 4–6 хвилин CPU-only inference
- **Немає GPU** — на MacBook Air або стандартному сервері без GPU cloud API незамінний
- **Розробка та прототипування** — швидко тестувати нові ідеї без інфраструктури
- **Багатомовний контент** — GPT-4o-mini слідує інструкціям щодо мови

**Уроки з цього завдання:**
- GPT-4o-mini дає продакшн-якість за мінімальну вартість ($0.0002–0.0004 за виклик)
- JSON mode (`response_format: json_object`) повністю усуває проблему невалідного JSON
- 100% recall задач навіть на найскладнішому датасеті (6/6)
- Загальна вартість 3 запитів — **менше 0.1 центу**

### 3. Гібридний підхід (ensemble / fallback)

Найбільш практичний підхід для production:

```python
def extract_with_fallback(text: str) -> dict:
    """
    Спочатку Ollama (дешево, локально), якщо JSON невалідний → OpenAI (хмара).
    """
    result = extract_meeting_data(text, provider="ollama")

    if result["json_valid"]:
        return result["result"]

    print("Ollama failed, falling back to OpenAI...")
    result = extract_meeting_data(text, provider="openai")
    return result["result"]
```

**Переваги гібриду:**
- 70–80% запитів (прості тексти) обробляє Ollama за $0
- 20–30% складних або великих текстів → OpenAI за $0.0003/запит
- Загальна вартість знижується в 3–5 разів порівняно з чистим OpenAI

**АЛЕ зважаючи на результати експерименту:**
- JSON-валідність ≠ якість даних. Llama2 повертав валідний JSON з помилковими власниками 
- Краще використати **другий рівень валідації** — перевірити чи всі owners з результату згадуються в оригінальному тексті, інакше → fallback

### 4. Розширення агента

**Підтримка мов (мультилінгвальність):**
- В промпті явно вказати: "Поверни summary українською мовою, незалежно від мови оригіналу"
- Експеримент показав: 7B модель ігнорує цю інструкцію для технічного тексту → можливо, потрібна 13B+ або preprocessing
- Альтернатива: translate(EN) → extract → translate(UA), але втрачаються нюанси

**Додавання confidence_score — обережно з підходом:**

Перша інтуїція — попросити модель повертати число `0.95` для кожного поля:
```json
{"owner": "Іван", "task": "UI прототип", "confidence": 0.95}
```

**Чому це не працює:** LLM — імовірнісна модель, і коли ти просиш її саму поставити собі оцінку від 0 до 1 без чіткого визначення шкали, вона видає **випадкове число, яке "звучить впевнено"**. Сьогодні `0.95`, завтра на тих самих даних `0.87`, і це число не корелює з реальною коректністю результату. Модель не має інтроспекції щодо власної впевненості — вона генерує токени, що максимізують probability наступного токена, не self-assessment.

**Що працює натомість:**

1. **Дискретна шкала з чіткими критеріями** в промпті:
   ```
   confidence: "high" | "medium" | "low"
   - high: власник прямо названий у тексті, дедлайн чітко вказаний
   - medium: власник зрозумілий з контексту, дедлайн приблизний
   - low: інформація вгадана, можлива інтерпретація
   ```
   Це дає моделі якорі замість абстрактних чисел.

2. **Self-consistency**: запустити 3-5 разів з різним seed/temperature, порівняти результати. Власник, який зʼявляється у всіх запусках, отримує high confidence; той, що варіюється — low. Це **обʼєктивна** метрика, не вигадана моделлю.

3. **External verification**: перевірити чи витягнуте значення дослівно є в оригінальному тексті (regex match для імен, парсинг дат). Якщо `owner` не знайдено в тексті — флаг.

4. **Logprobs** (тільки для OpenAI): API може повертати log-probabilities токенів. Низькі logprobs = модель сама не була певна під час генерації. Це найближче до "справжнього" confidence, бо береться з внутрішніх станів моделі, а не з її self-report.
